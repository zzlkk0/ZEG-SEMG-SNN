# Delay 分支重训：对齐论文精度 + 为稀疏调度打基础（交接给训练服务器）

> 自包含任务说明。背景：部署端把 `semg_snn_nexys4ddr_vivado` 里已上板的整数
> Delay-SNN，和 Scrugli et al. *"sEMG-based Gesture Recognition with Spiking
> Neural Networks on Low-power FPGA"*（DASIP 2024）做了逐项对比，发现两者
> **MOPS 完全相同（2,336,000，逐位一致）、拓扑逐层相同**——本项目的 Delay 分支
> 就是对这篇论文架构的复刻。论文精度 85.6%（含投票后处理），本项目严格精度
> 83.9305%（11,276 窗，无平滑）。本任务**只针对 Delay 分支**，目标是把精度往
> 论文的方向拉近，并为后续硬件侧的稀疏调度优化做准备。**不涉及 Context/
> Hybrid，不涉及硬件功耗/占空比实现**（那部分由部署端在 RTL/板级完成，不需要
> 训练侧介入）。

## 0. 一句话任务

对现有 Delay-SNN（`semg_snn_fpga_reproduction/runs/delay62_finetune/best.pt`
或其等价来源）重新训练/调优，**拓扑和定点格式保持完全不变**，目的有两个：
（1）通过对齐论文的评估方法论和训练细节，尽量缩小与论文 85.6% 的精度差距；
（2）在训练目标里加入脉冲稀疏度正则，让模型学出更稀疏的激活，为部署端后续
实现"跳过非活跃突触"的事件驱动硬件调度提供基础。

## 1. 精度差距分析（背景，你不需要重新推导，直接按这个走）

对比论文（见其正文与 Table 1/2/3）与本项目现状，差距大概率来自三个方向，
**不是模型架构能力差距**（MOPS/拓扑已确认相同）：

1. **论文的 85.6% 已经包含时域投票后处理**：丢弃与前后不连续的孤立误判标签，
   用上一个有效分类结果替代。本项目当前报的是逐窗严格精度，没有这层平滑。
2. **训练细节可能不同**：论文用 SLAYER/LAVA 框架，loss 用 `slayer.loss` 的
   `SpikeRate` 类（真实类别目标发放率 0.2，其余类别目标发放率 0.03），
   Adam，lr=0.001，batch=32，早停（10轮无提升即停）。
3. **窗口标注纯度规则可能不同**：论文的规则是"窗口内 ≥80% 样本标为该手势才
   标记为该手势；100% 标为 rest 才标记为 rest；不满足则从训练/测试中剔除"。

## 2. 需要做的事

### 2.1 复现论文式的时域投票后处理，两种精度都要报

在**现有测试集协议不变**（NinaPro DB5 Ex1, repetition 5 严格测试窗）的前提下：

- 报告**逐窗严格精度**（就是当前的 83.9305% 这个口径，用于确认没有退化）。
- 额外实现论文式的投票/平滑后处理（丢弃孤立的不连续标签，恢复上一个有效分类
  结果——论文没有给出精确到帧的算法伪代码，请按这个语义实现：对逐窗预测序列
  做一次遍历，如果某个预测标签和它前一个"已接受"的输出不同、且下一个窗口的
  预测也不支持这次切换（即这是孤立的单点跳变），则丢弃这次预测、沿用上一个
  已接受的标签），报告**加了投票后的精度**。
- 给出这个投票算法的**确定性 numpy 实现**（不依赖 torch），因为它最终要在
  主机端（Python host）复现，不在 FPGA 上跑。
- 如果论文的 200ms tolerance 评估方式（±200ms 内 rest 和该手势都算对）也想
  对齐，请**额外报告**这个口径下的精度，但不要用它替代上面两个主口径。

### 2.2 训练配方对齐或至少如实报告

- 优先尝试对齐论文的训练配方：loss 换成/参考 SpikeRate 风格（真实类别目标
  发放率、其余类别目标发放率两个超参），Adam lr=0.001，batch=32，早停
  patience=10。
- 如果对齐后精度没有改善或变差，**如实报告两种配方的对比结果**，不要只报
  更好看的那个。
- 报告当前实际使用的训练配方细节（优化器、loss、lr、batch、epoch数/早停
  条件、数据增强、随机种子），无论是否与论文一致。

### 2.3 复核窗口标注纯度规则

- 检查当前数据准备管线的窗口标注规则是否符合"≥80%手势样本→标为该手势；
  100% rest 样本→标为 rest；不满足→剔除"这条规则。
- 如果不一致，请**額外提供**按论文规则重新准备数据后的训练/评估结果，与现有
  规则的结果并列报告，说明规则差异对精度的实际影响有多大。
- 不要求必须切换到论文的规则作为最终交付标准（现有规则可能是有意为之），但
  必须让部署端清楚知道两者的差异和各自的精度数字。

### 2.4 脉冲稀疏度正则化（为后续硬件优化打基础，非精度诉求）

- 在训练 loss 里加入一项**鼓励脉冲稀疏**的正则（例如对每层脉冲发放率做 L1/L2
  惩罚，或采用类似论文 SpikeRate 的显式目标发放率约束），目标是让模型在**不
  明显牺牲精度**的前提下产生更稀疏的激活模式。
- 用与论文 Eq. 4（sparsity-hw）同风格的口径报告稀疏度：
  `sparsity = (1 - 活跃分组数/总分组数) × 100%`，分组大小请按 **1**（即逐脉冲，
  不分组）来报告，因为部署端当前的硬件是逐周期处理单个突触，不是论文那种
  4-脉冲一组的并行架构。同时报告加正则前后的原始稀疏度（活跃脉冲比例）对比。
- 如果稀疏度正则显著伤害精度（例如掉超过 1-2 个百分点），请报告帕累托前沿
  （几组不同正则强度下的精度-稀疏度数据点），让部署端自己权衡，不要擅自选一
  个折中方案直接作为唯一交付。

### 2.5 权重格式：必须与当前部署格式完全兼容，不允许更改

这是硬约束。重训后的权重必须能**直接替换**现有部署里的
`weights/layer*_weights.mem` / `weights/layer*_delays.mem` /
`weights/snn_params.svh`（或其等价来源的 state_dict），不需要部署端重做
HLS/RTL：

- 拓扑不变：96→64→128→64→13，前三层每神经元一个整数轴突延迟（0–62），
  第四层无延迟。
- 权重量化不变：每层对称 INT8。
- 膜电位格式不变：signed Q8。
- 衰减不变：`beta = 230/256`（k/256 网格），如果稀疏正则导致最优衰减值漂移，
  仍需量化回 k/256 网格并报告新的 k 值。
- 舍入/复位不变：signed round-to-nearest-even；发放后 hard reset 到零。
- 如果因为稀疏正则或训练配方调整导致某些超参数（如阈值）需要变化，必须仍然
  落在现有 RTL 支持的定点格式内，并在报告里写清楚新旧数值对比。

### 2.6 精度报告（全测试集，不能少）

在完整 NinaPro DB5 Ex1 repetition 5 严格测试集（11,276 窗）上报告：

- 基线（当前 83.9305%）
- 训练配方对齐后（若有变化）
- 加投票后处理后（逐窗基础上 + 投票）
- 加稀疏正则后（精度 + sparsity 指标，帕累托多点）
- 以上各项两两组合的最终推荐配置的精度，以及该配置的完整训练配方记录

## 3. 验收标准

1. 权重格式与现有部署 100% 兼容，可直接替换，无需改动 HLS/RTL/RTL 位宽。
2. 投票后处理有确定性 numpy 实现，可在主机端复现。
3. 精度报告覆盖：基线、配方对齐、投票后、稀疏正则后，且诚实报告每一项对精度
   的实际影响（包括没有改善或变差的情况）。
4. sparsity 指标按分组大小=1 的口径报告，附帕累托数据点。
5. 不擅自决定最终"最优"配置替代如实报告——把选择权留给部署端。

## 4. 明确不在本任务范围内（避免越界返工）

- **不涉及功耗优化的硬件实现**（占空比/时钟门控/低功耗状态机）——这是部署端
  在 RTL/板级完成的工作，训练侧不需要、也无法实现这部分。
- **不涉及 Context/Hybrid 分支**——本任务只针对 Delay。
- **不要求切换到超低功耗 FPGA 器件**——现有 Nexys4 DDR (XC7A100T) /
  EBAZ4205 (XC7Z010) 目标不变，稀疏正则的价值是给部署端后续做事件驱动调度
  提供数据基础，不是立刻就要换硬件。
